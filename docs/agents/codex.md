## 2. Built-in skills

Bundled by OpenAI. On disk at `$CODEX_HOME/skills/.system/`, stamped with a
`.codex-system-skills.marker` — that marker is how you tell a built-in from something you installed.

| Skill | Does what |
|---|---|
| `skill-creator` | create or update a skill |
| `skill-installer` | install curated skills from `openai/skills` or another repo |
| `plugin-creator` | scaffold a plugin directory and marketplace entry |
| `openai-docs` | OpenAI and Codex documentation, including Codex's own self-knowledge |
| `imagegen` | generate or edit raster images |
| `review-agent` | read-only defect-first review of a change. **Not user-invocable** — its own description says "use when another agent **delegates** review", and it does not appear in the model-visible skill list. It is what `codex review` delegates to |

> **The built-in set varies by platform and version, and neither source is complete.** The official
> documentation lists *Skill Creator, Skill Installer, Atlas Control (macOS), Exec Plan, GitHub Fix
> CI, Linear, OpenAI Docs*. This Windows machine has *imagegen, openai-docs, plugin-creator,
> review-agent, skill-creator, skill-installer*. Three names overlap. **Both lists are right for
> their context** — check `.system/` on the machine you care about.

## 3. Tools

Not documented as a list. `codex debug prompt-input` renders the model-visible prompt including
tool definitions, which is the way to see them. MCP servers add tools on top; this installation had
`context7` (HTTP) and `node_repl` (local) configured in `config.toml`.

## 4. Installable — official

Nothing here is available until installed, **however pre-installed it looks**. The desktop app marks
all of it `Personal`, as opposed to `System`.

### Plugins

`/plugins` in-session, or `codex plugin add <name>@<marketplace>`.

| Marketplace | Plugins | Notes |
|---|---|---|
| `openai-primary-runtime` | `documents` (Word/Google Docs), `pdf`, `spreadsheets` (Excel/Sheets, plus `excel-live-control` for a live workbook), `presentations` (PowerPoint/Slides), `template-creator` | ship enabled on a normal install, but are still installed rather than built in |
| `openai-bundled` | `browser` (in-app browser), `chrome` (the user's real Chrome, with its logged-in state), `visualize` (charts, maps, diagrams, 3D, UI previews), `codex-app-tools`, `computer-use` (**control desktop apps on Windows**), `latex` (Tectonic + TeX Live) | `computer-use` and `latex` were **not installed** here |
| `openai-curated` | ~45 third-party: `linear`, `github`, `slack`, `figma`, `stripe`, `vercel`, `netlify`, `sentry`, `notion`, `posthog`, `shopify`, `glean`, `atlassian-rovo`, `expo`, `zoom`, `box`, `digitalocean`, `hugging-face` … | mostly MCP wrappers |
| `openai-curated` | **`codex-security`** | ⚠️ **gated** — see below |

**`codex-security`** ⚠️ is the deepest capability either agent has at any stage, and the hardest to
get. Ten skills forming a pipeline rather than one pass: entry points `security-scan`,
`deep-security-scan`, `security-diff-scan`; stages `threat-model` → `finding-discovery` →
`attack-path-analysis` → `validation` → `triage-finding` → `fix-finding`; and `track-findings`,
which writes results into Linear, Jira, GitHub issues or a draft GitHub security advisory.

> **"Running scans requires Codex Security access."** Installing the plugin is not enough. On this
> machine `codex plugin list` reported it `installed, enabled` while its skills were **never
> exposed to the model** — typing `$security-scan` did nothing. Install via the desktop app's
> plugin list, or the separate npm package `npx @openai/codex-security`.

## 5. Extension points

| | Path | Scope |
|---|---|---|
| Instruction file | `AGENTS.md` — every level from repo root to cwd, **concatenated, not overridden**. `AGENTS.override.md` replaces one level. `project_doc_max_bytes` = **32 KiB by default, configurable**; whether it bounds the combined chain or each file is disputed between two official pages — `research/MATRIX.md` section 2 | project + `~/.codex/AGENTS.md` |
| Skills | `.agents/skills/` | project, user (`~/.agents/skills`), admin (`/etc/codex/skills`) |
| MCP | `[mcp_servers.<name>]` in `config.toml` | project `.codex/config.toml`, user `~/.codex/config.toml` |
| Subagents | `.codex/agents/*.toml` — `sandbox_mode` (`read-only`, `workspace-write`, `danger-full-access`), `model`, `developer_instructions`; capped by **`agents.max_concurrent_threads_per_session`** (legacy alias `agents.max_threads`). `max_depth` and `job_max_runtime_seconds` appeared in an earlier draft of this file and are **not** in the current configuration reference — treat as `(unverified)` | project |
| Hooks | **`<repo>/.codex/hooks.json` and `~/.codex/hooks.json`**, plus plugin-bundled `hooks.json`. All layers load; none replaces another. **11 events**: `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse` (**can block**), `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop`, `Stop`. Handlers: `command`, `mcp_tool` — `prompt` and `agent` are parsed but skipped | project, user, plugin |
| Plugins | `.codex-plugin/plugin.json` + optional `skills/`, `commands/`, `agents/`, `hooks.json`, `.mcp.json`, `.app.json`, `assets/` | marketplace |

**Skill precedence**, per the official documentation, highest first:
`$CWD/.agents/skills` → parent folders → `$REPO_ROOT/.agents/skills` → `$HOME/.agents/skills` →
`/etc/codex/skills` → built-in.

**Configuration precedence:** CLI flags and `--config` → profile → project `.codex/config.toml`
root-to-cwd → user → `/etc/codex/config.toml` → defaults. **A project marked untrusted skips every
project-scoped `.codex/` layer** — a security boundary Claude Code has no equivalent for.

**Skills are invoked with `$`, session commands with `/`.** `$skill-installer`, not
`/skill-installer`.

## 6. How to enumerate this yourself

```bash
codex debug prompt-input        # what the model actually sees, incl. every skill and its root
codex plugin list               # installed and available plugins, per marketplace
codex --help                    # CLI subcommands
ls $CODEX_HOME/skills/.system/  # the built-ins
```

`codex debug prompt-input` is the one that settles arguments: it prints a `<skills_instructions>`
block with each skill and the root it resolved from. **A `SKILL.md` on disk is not a loaded skill**
— a plugin can read `installed, enabled` while contributing nothing to that list.

In the **desktop app**, type `/` and `$` and read the pickers; the app labels every skill `System`
or `Personal`.

## 7. Surface differences

**Officially:** "Standalone skills are available in the ChatGPT desktop app, Codex CLI, and IDE
extension." Plugin-bundled skills additionally work "in Chat and Work across ChatGPT on the web,
desktop, and mobile."

**In practice they diverge, and the CLI is not a proxy for the app:**

- The app's picker showed `Plugin Management` (from `openai-curated-remote`); the CLI's
  `prompt-input` list did **not** contain it.
- `codex debug prompt-input` on the CLI listed **16** skills from 6 roots, and `openai-curated` was
  **not among the roots**.
- Known open issue: [openai/codex#28505](https://github.com/openai/codex/issues/28505) — *"Codex app
  does not index personal skills from `~/.agents/skills` for `$` invocation."* Project-scoped
  `.agents/skills` in the app is **(unverified)**, and it matters here because that is where
  `install.py` writes. It was confirmed loaded on the **CLI**.
- `/pet`, `/goal` and `/init` descriptions exist in the app menu but not in the official command
  reference.

**IDE extension: not checked at all.**
